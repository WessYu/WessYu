## Component Vault

> **AI can generate code. The repository should still decide what is allowed.**

[Component Vault](https://github.com/WessYu/component-vault) is the project that best represents how I approach frontend engineering.

It started as a component library and evolved into a developer tool for **component governance, AST-based analysis and automated enforcement**.

The core idea is simple: frontend rules should not live only in documentation or code review. When a rule matters, tooling should be able to understand it, report violations and — when safe — help fix them.

```text
Codebase
   ↓
TypeScript Compiler API
   ↓
Component Vault Guard
   ├── component rules
   ├── semantic rules
   ├── baseline / migration
   └── deterministic autofix
   ↓
CLI · CI · Pull Requests
```

### CLI

```bash
npx @wess2001/component-vault@latest init
npx component-vault analyze
npx component-vault scan
```

## Engineering approach

I try to solve the problem behind the feature, not just implement the feature itself.

- **Reusable over repetitive** — components should reduce complexity, not hide it.
- **Explicit over clever** — APIs and conventions should be understandable to the next developer.
- **Accessible by default** — responsive and usable interfaces are part of the implementation.
- **Automate recurring problems** — if a rule can be checked reliably, tooling should help enforce it.
- **Optimize for change** — code should remain understandable when requirements inevitably move.

This is the direction that took my work from building interfaces toward **component governance and developer tooling**.
